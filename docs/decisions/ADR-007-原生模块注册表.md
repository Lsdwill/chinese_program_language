# ADR-007：原生模块注册表与运行时解耦

## 状态

已接受，第二阶段 S1。

## 背景

v0.3.0 的标准模块构造函数集中在 VM 文件中。第二阶段需要增加 SQLite、HTTP、能力检查和 LSP 元数据。如果新模块继续直接堆叠在 VM 中，编译器、项目检查器和 LSP 无法复用模块信息，也会形成更多耦合。

## 决定

新增不依赖 VM 的 internal/native 包，负责保存原生模块描述：

- 模块名称；
- 模块版本；
- 所需能力；
- 确定性名称查询；
- 确定性导出元数据的后续扩展。

实际函数调用仍然通过 VM 的受控 Value 和 NativeFunc 接口执行。第二阶段不承诺第三方 Go 动态插件 ABI。

## 约束

- 注册名不能为空；
- 同名模块不能重复注册；
- 能力列表去重并排序；
- 查询返回副本，不能修改注册表内部状态；
- 未知模块不能通过注册表伪造为已存在模块；
- 标准模块的用户可见 API 继续由规范和一致性测试定义。

## 影响

未来标准库拆分为独立包时，注册表可以被 VM、项目检查器和 LSP 共同使用。当前版本先保留 StandardModule 的行为分发，逐步迁移实现。
