# ADR-008：资源管理器与显式关闭语义

## 状态

已接受，第二阶段 S1。

## 背景

SQLite 连接、事务、HTTP 监听器和响应体都拥有宿主资源生命周期。只依赖 Go 垃圾回收无法保证及时释放，也无法表达事务回滚和网络监听关闭。

## 决定

新增独立的 internal/resource 包：

- Native 模块注册资源和 io.Closer；
- Resource Manager 生成不透明 Handle；
- 单个资源关闭必须幂等；
- VM 关闭时按注册的逆序关闭剩余资源；
- 关闭错误汇总后返回；
- VM 终结清理只作为兜底，不能替代华言代码的显式关闭；
- 第二阶段增加 尝试/最后 语义，用于业务级资源清理。

华言侧资源对象只能由原生模块创建，不能 JSON 序列化、不能作为字典键、不能由用户伪造。

## 关闭顺序

同一 VM 中后注册的资源先关闭：

~~~text
数据库 → 事务 → 响应
关闭顺序：响应 → 事务 → 数据库
~~~

这符合嵌套资源的生命周期直觉。

## 被拒绝方案

- 只依赖 Go finalizer：关闭时间不确定；
- 让每个标准模块自己维护资源表：无法统一泄漏检查；
- 把资源暴露成普通记录：用户可以伪造和错误序列化；
- 立即实现华言自有 GC：超出第二阶段必要范围。
