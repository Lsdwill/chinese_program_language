# 华言中文数据库查询 DSL 设计

状态：v0.4 第一版已实现

## 目标

华言程序不直接编写 SQL，也不需要知道底层数据库引擎名称。源码只使用中文数据库模块；底层采用 SQLite 作为嵌入式存储引擎。表、字段、条件和排序使用华言值与中文 API 表达，动态数据永远不通过字符串拼接进入数据库。

## 第一版调用形式

第一版中文标准模块 API 已实现；查询语法糖也已接入，并且对旧代码采用上下文识别，不会把普通变量“选择”强制变成关键字：

~~~text
导入 标准.数据库 为 数据库

让 库 = 数据库.打开("数据/图书馆.db")
数据库.建表(库, "图书", 记录 {
    编号: "文字",
    书名: "文字",
    作者: "文字"
})
数据库.插入(库, "图书", 记录 {
    编号: "B001",
    书名: "活着",
    作者: "余华"
})
让 图书 = 数据库.选择(库, "图书", 记录 {编号: "B001"})
打印(图书[0].书名)
数据库.关闭(库)
~~~

API 不暴露 SQL 字符串。表名和字段名由运行时校验为安全标识符；记录值通过参数绑定传递。

查询语法糖：

~~~text
让 结果 = 选择 图书 从 库
    其中 编号 等于 "B001"
    排序 书名 升序
    限制 20
结束
~~~

只有“选择”后紧接表名，并形成“从 数据库变量”结构时才进入查询解析；`让 选择 = ...` 等 v0.3 代码保持有效。

## API

~~~text
打开(路径) -> 数据库资源
关闭(数据库资源)
建表(数据库, 表名, 字段定义记录)
插入(数据库, 表名, 记录) -> 执行结果
选择(数据库, 表名, [条件记录]) -> 记录列表
选择一行(数据库, 表名, [条件记录]) -> 记录或空
更新(数据库, 表名, 修改记录, [条件记录]) -> 执行结果
删除(数据库, 表名, [条件记录]) -> 执行结果
开始事务(数据库) -> 事务资源
提交(事务)
回滚(事务)
最后插入编号(执行结果) -> 整数
受影响行数(执行结果) -> 整数
~~~

条件记录使用字段等值匹配作为第一版范围。后续增加中文条件构造器，例如 `大于`、`包含`、`且`、`或`，而不是允许用户传入 SQL 片段。

## 设计边界

- 第一版不接受原始 SQL API；
- 只允许安全的表名、字段名和有限数量的返回行；
- 底层数据库的空值、整数、小数、文字、二进制分别映射为空、整数、小数、文字、字节串；
- 数据库资源使用 VM 资源管理器，关闭后再次访问返回资源错误；
- 数据库操作需要“数据库”能力，数据库路径仍受文件运行上下文约束；
- 事务错误自动回滚，VM 关闭时未完成事务先回滚。

## 后续语法糖

在 API 稳定后，再增加可选中文语句糖：

~~~text
选择 图书
    其中 编号 等于 "B001"
    排序 书名 升序
    限制 20
结束
~~~

语法糖必须编译为同一个查询 AST，不能形成第二套数据库语义。
